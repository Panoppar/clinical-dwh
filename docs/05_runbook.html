Prerequisites

  • Docker Desktop with Compose v2
  • Outbound internet access to 5 government API hosts (NSO, BMA, DIW, DDS, HDC) and GitHub (if re-fetching anything) — this pipeline has no offline mode
  • Python 3 with openpyxl only if regenerating Excel\KPI_Tree_and_Dashboard_Design.xlsx or these docs

First-Time Deploy

  1. Clone and configure environment

    Copy-Item .env.example .env
Copy-Item seaweedfs_s3_config.json.example seaweedfs_s3_config.json
# Edit BOTH files: change every ChangeMe_* password.
# The access/secret key pair must match between the two files --
# .env is read by elt-runner; seaweedfs_s3_config.json is read
# directly by the SeaweedFS binary, not env-templated.

  2. Bring up infrastructure

    docker compose up -d warehouse-db landing-zone metabase
docker compose ps   # wait for warehouse-db and landing-zone to show "healthy"

    warehouse-db's healthcheck is mysqladmin ping; landing-zone's accepts any HTTP response (even 403) as healthy -- confirms the SeaweedFS S3 gateway is reachable, not that credentials are correct yet.

  3. Build and run the pipeline

    docker compose build elt-runner
docker compose run --rm elt-runner

    One-shot batch job. Ingests all 5 sources (DIW's amphoe crawl takes ~70s; HDC's full report crawl takes ~15-20 min at its 0.6s throttle -- this is the long pole of a first deploy), shreds to Bronze, cleanses to Silver, builds Gold. A source that's down (see DDS, below) logs a warning and the run continues -- it will NOT abort the whole deploy.

Verify the Deploy

The pipeline prints a row-count summary on success. Expected figures (2026-10-26 baseline; BMA/HDC will grow as those sources publish new fiscal years/reports):

TableExpected rows
✓bronze.api_nso_income15,400
✓bronze.api_bma_community6,027
✓bronze.api_diw_factory13,683
⚠bronze.api_dds_disease_ranking0 -- expected while DDS's backend is down (see Troubleshooting)
✓bronze.api_hdc_observations163,219
✓gold.dim_geography451 (77 provinces + 67 districts + 307 subdistricts)
✓gold.obt_regional_composite_index154 (province x year combinations)

Spot-check manually if any number looks off:

docker compose exec warehouse-db mysql --default-character-set=utf8mb4 -u root -p `
  -e "SELECT COUNT(*) FROM gold.fact_hdc_observation;"
Always pass --default-character-set=utf8mb4 explicitly on any manual mysql client invocation. Confirmed by direct testing: the MySQL server image's own bundled client defaults to latin1 and silently corrupts Thai string comparisons with no error raised.

Metabase Bootstrap

A brand-new Metabase container has no admin account and no database connections -- first boot shows a setup wizard. Two ways to complete it:

Option A -- UI wizard

Open http://localhost:3000, follow the prompts: create the admin account, then add a database connection (MySQL, host warehouse-db, port 3306, database gold, user metabase_ro, password = DWH_METABASE_RO_PASSWORD from .env).

Option B -- API (scriptable, used for this deploy)

Get the setup token, then POST the admin user. The embedded database object in /api/setup was unreliable on v0.50.19 in practice -- it silently succeeded without creating a connection. Add the database as a separate explicit call instead:

$token = (Invoke-RestMethod http://localhost:3000/api/session/properties).'setup-token'
Invoke-RestMethod -Method Post http://localhost:3000/api/setup -ContentType 'application/json' -Body (@{
  token = $token
  user = @{ first_name='Admin'; last_name='User'; email='you@example.com'; password='...'; site_name='clinical-dwh' }
  prefs = @{ site_name='clinical-dwh'; site_locale='en'; allow_tracking=$false }
} | ConvertTo-Json -Depth 5)

# Then log in and add the real database connection explicitly:
$session = (Invoke-RestMethod -Method Post http://localhost:3000/api/session -ContentType 'application/json' `
  -Body (@{ username='you@example.com'; password='...' } | ConvertTo-Json)).id
Invoke-RestMethod -Method Post http://localhost:3000/api/database -Headers @{'X-Metabase-Session'=$session} `
  -ContentType 'application/json' -Body (@{
    engine = 'mysql'; name = 'gold'
    details = @{ host='warehouse-db'; port=3306; dbname='gold'; user='metabase_ro'; password='...'; ssl=$false }
  } | ConvertTo-Json -Depth 5)

Verify sync completed: GET /api/database/{id}?include=tables, check every table shows "initial_sync_status":"complete".

A default "Sample Database" (Metabase's own H2 demo dataset, id=1 on a fresh instance) is added automatically during setup. Remove it for a clean workspace: DELETE /api/database/1 with the admin session header.

Day-2 Operations

  • Re-run the pipeline any time: docker compose run --rm elt-runner. Idempotent -- the landing zone skips re-storing identical bytes, each layer's DDL drops/recreates its own tables.
  • Re-run just one source (faster than a full run while iterating): 
    docker compose run --rm elt-runner python -c "import ingest_api_nso, extract_load_api_nso; ingest_api_nso.run(); extract_load_api_nso.run()"
  • Regenerate these docs after any schema change -- dump the schema, then run the generator: 
    docker compose exec warehouse-db mysql --default-character-set=utf8mb4 -u root -p `
  -N -e "SELECT table_schema,table_name,column_name,column_type,is_nullable,column_comment,ordinal_position FROM information_schema.columns WHERE table_schema IN ('bronze','silver','gold') ORDER BY 1,2,7;" `
  > "$env:TEMP\schema_dump.tsv"
python docs\build_html_docs.py
  • Browse the landing zone at http://localhost:8888/buckets/landing-zone/ -- SeaweedFS's own Filer web UI (folders by source, file download/preview, upload/new-folder). Already running inside the landing-zone container via the server command; exposed to the host via LANDING_FILER_UI_HOST_PORT (default 8888) in docker-compose.yml. No separate client needed -- this is the "DBeaver for the landing zone."
  • Rebuild the elt-runner image after any Python/requirements change: docker compose build elt-runner

Troubleshooting

DDS returns 500 on every request. Check for "could not find driver (Connection: pgsql...)" in the response body -- that's DDS's own backend missing its PostgreSQL PHP driver, not fixable from this side. Nothing to do but wait and re-run ingest_api_dds.run() periodically.
NSO requests return an HTTP 418 block page. The WAF in front of NSO's API blocks the default requests/curl User-Agent. Confirm ingest_api_nso.py still sends User-Agent: Mozilla/5.0 kmch-phase3-nso/1.0 -- if NSO changes their WAF rules, the fix is a different UA string, not a code redesign.
landing-zone container is "unhealthy". Its healthcheck accepts any HTTP response as healthy (even 403) -- a real failure means the container can't be reached at all. Check docker compose logs landing-zone; a common cause is seaweedfs_s3_config.json missing (copy it from the .example if you skipped that step).
A full pipeline run seems to hang for ~15-20 minutes. That's the HDC crawl (119 reports x up to 5 years x 2 zones, throttled 0.6s between requests) -- not a hang. Watch the log for [ingest_api_hdc] (N/119)... lines advancing.

Full Reset

docker compose down -v   # removes containers AND volumes -- landed objects, warehouse data, Metabase state all gone
docker compose up -d warehouse-db landing-zone metabase
docker compose run --rm elt-runner
# then redo the Metabase Bootstrap section above -- a fresh volume means a fresh setup wizard
This deletes everything: every landed API response in SeaweedFS, every Bronze/Silver/Gold row, and the entire Metabase instance (admin account, saved questions, dashboards). Only run this when you genuinely want to start over.
