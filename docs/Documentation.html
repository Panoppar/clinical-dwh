clinical-dwh — Full Project Documentation

Complete reference for the project built in this session: a local Dockerized Medallion (Bronze/Silver/Gold) MySQL data warehouse with Metabase BI, unifying 9 fragmented Thai government and local health/economic data sources for a hospital catchment area in Bangkok. Includes the full build history and a complete data dictionary for every table in every tier.

Build Timeline

The project was built bottom-up, one layer and one theme at a time, with each stage fully verified (row-count reconciliation, aggregate-row scanning, idempotency checks) before moving to the next.

1. Bronze layer — raw ingestion (9 sources, 62 tables)

DOPA, HDC manual exports, Lat Krabang, KMCH, factory list, DDS health region, NSO, HDC region 6–13, other_health — each loaded 1:1 from its source files with no interpretation, typed as text/varchar, tagged with source file name and ingestion batch ID for traceability.

2. Silver layer — conform and type (35 tables, 3 themes)

Built in 3 stages matching the Gold build order: Population & Demographics (DOPA, NSO, other_health), Health Surveillance & Disease (HDC_manual, HDC_region6-13, DDS, other_health), Local-Area & Economic (Lat Krabang, KMCH, Factory list, other_health). Each table conformed and typed within its own source — not yet joinable across sources.

3. KPI catalog proposal

A comprehensive KPI catalog was drafted directly from the Silver-layer data, organized by the same 3 themes, with every KPI tied to a specific achievable Silver table/column.

4. Gold layer plan

Architecture decided: a Star Schema foundation (dim_/fact_) feeding two derived consumer layers — denormalized OBT/agg tables for Metabase BI, and flat feature-store tables for ML. Planned and approved before implementation began.

5. Gold Stage 1 — Population & Demographics

dim_date, dim_geography (with a Python cross-source geography normalization script), dim_age_sex, dim_population_component; fact_population_by_area, fact_population_age_sex; obt_population_by_geography, agg_population_summary_yearly, feat_geography_month. Fixed a dim_geography dedup bug (historical admin-name reclassifications) and a sex-normalization join bug along the way.

6. Gold Stage 2 — Disease Surveillance

dim_disease (scoped per source system, 7 disjoint vocabularies), fact_disease_event, fact_disease_incidence_hdc (unpivoted from HDC's fiscal-year monthly columns); obt_disease_surveillance, agg_disease_kpi_monthly. Found and fixed a 42.5-million-row join fan-out and an 85-minute full-table-scan performance bug.

7. Gold Stage 3 — Economic & Local-Area

dim_factory, dim_place (8 heterogeneous KMCH-catchment sources); fact_factory_registration, fact_catchment_place; obt_economic_by_geography, agg_economic_summary_yearly, feat_factory. Found and fixed an 815-row join fan-out from the same root cause pattern as Stage 2's.

8. Gold layer HTML documentation

A dedicated architecture reference (docs/06_gold_layer_documentation.html) covering the Gold layer design, every table's grain and gotchas, and the KPI catalog.

9. Metabase dashboards

Connected Metabase read-only to the Gold schema via the metabase_ro user. Built a Population Overview dashboard with province snapshots, long-run trends, and a custom Thailand province choropleth map (GeoJSON from OpenGISData-Thailand, matched on DOPA province codes).

10. Presentation & this documentation

An HTML slide presentation summarizing the project (KMITL/Presentation/Presentation.html) and this full project documentation with a complete data dictionary for every tier.

Engineering Notes

Join fan-out, twice: agg_disease_kpi_monthly's YoY self-join matched on district-level geo_key while the real fact grain was per-hospital (hospcode+areacode) — 507K facts exploded to 42.5M rows. fact_factory_registration had a related bug: resolving ambiguous subdistrict names via a two-step inline LEFT JOIN fanned out before disambiguation could apply — 815 duplicate rows. Both fixed by pre-resolving geography in a deduplicated lookup table before the main join.
85-minute full table scan: even after the join logic was fixed, no index existed on the facility-grain key used in the self-join. Added a composite index; the same query then completed in under 2 minutes.
Idempotency / FK ordering: rerunning the pipeline without a full schema wipe initially failed — DROP TABLE on a dimension failed when a fact table (built in a prior run) still held a foreign key into it. Fixed with SET FOREIGN_KEY_CHECKS=0/1 wrapping every referenced dimension's rebuild script.
is_headline_total gotcha: summing fact_population_age_sex by is_headline_total=1 alone returned 2–4× the real population — the flag only narrows to the right indicator, not to a single (sex, age) slice. Always combine with sex='total' AND age_qualifier='total'.
Verification discipline: every fact table's row count is reconciled exactly against filtered Silver source counts; an aggregate-row scanner tool catches stray rollup rows; idempotency is verified by rerunning on top of existing data; real-world figures (e.g. Bangkok population 5,455,020, Dec-2024) are cross-checked against multiple independent sources throughout the build.
