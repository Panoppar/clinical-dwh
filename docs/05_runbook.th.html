คู่มือการติดตั้งใช้งาน (Runbook)

วิธีติดตั้งคลังข้อมูล (data warehouse) นี้ตั้งแต่เริ่มต้น: การตั้งค่าครั้งแรก การตรวจสอบผลลัพธ์ การเตรียม Metabase งานประจำวัน การแก้ไขปัญหาที่พบบ่อย และการรีเซ็ตทั้งหมด — แปลและปรับจาก 05_runbook.html (ฉบับภาษาอังกฤษ) ให้ตรงกับสถานะล่าสุดของโครงการ (อัปเดต 2026-11-04: ขยายช่วงข้อมูลประชากร DOPA เป็น 9 ปี, เพิ่มเขตการจ้างงานจังหวัดสมุทรปราการ/ฉะเชิงเทรา)
clinical-dwh · ภาษาไทย · สร้าง 2026-11-04
ไปที่: ข้อกำหนดเบื้องต้นติดตั้งครั้งแรก ตรวจสอบผลลัพธ์ตั้งค่า Metabaseโครงการ ML ที่เกี่ยวข้อง งานประจำวันแก้ไขปัญหารีเซ็ตทั้งหมด
เกี่ยวกับเอกสารนี้: นี่คือคู่มือสำหรับติดตั้งและทดสอบใช้งานคลังข้อมูล clinical-dwh บนเครื่องของคุณเอง (local deploy) เอกสารฉบับสมบูรณ์ภาษาอังกฤษพร้อมรายละเอียดเชิงเทคนิคเพิ่มเติมอยู่ที่ docs/05_runbook.html และสถาปัตยกรรม/แผนผังข้อมูลอยู่ที่ docs/01_architecture.html และ docs/02_data_dictionary.html

ข้อกำหนดเบื้องต้น

  • Docker Engine พร้อม Compose v2 (แนะนำ Docker Desktop สำหรับใช้งานบนเครื่อง Windows/Mac)
  • การเชื่อมต่ออินเทอร์เน็ตขาออก ไปยังแหล่งข้อมูลสด (live API) หลายแห่ง ได้แก่ NSO, BMA, DIW, HDC, DOPA, DOE (กรมการจัดหางาน), GitHub (ข้อมูลขอบเขตเขตปกครอง), router.project-osrm.org — ส่วน DDS และ Overpass/OSM ปัจจุบันถูกบล็อกจากฝั่งต้นทางเอง (ดูหัวข้อแก้ไขปัญหา) ไม่ใช่ปัญหาจากโค้ดนี้ — ไปป์ไลน์นี้ไม่มีโหมดออฟไลน์
  • ไฟล์ข้อมูลพื้นฐาน 4 ไฟล์ภายใต้ external-inputs/ (ตารางโยงตำบล, ข้อมูลประชากร DOPA สำรอง 2 ไฟล์, ข้อมูลใบอนุญาตแรงงานต่างด้าว BMA) — ไฟล์เหล่านี้ mount เข้าคอนเทนเนอร์โดยตรง ไม่ได้ฝังอยู่ใน image จึงแก้ไขได้โดยไม่ต้อง build ใหม่
  • Python 3 พร้อม pymysql บนเครื่อง host เฉพาะกรณีต้องการสร้างเอกสารชุดนี้ใหม่ (dump schema จาก information_schema)

การติดตั้งครั้งแรก

  1. คัดลอกไฟล์และตั้งค่าตัวแปรสภาพแวดล้อม

    Copy-Item .env.example .env
Copy-Item seaweedfs_s3_config.json.example seaweedfs_s3_config.json
# แก้ไขทั้งสองไฟล์: เปลี่ยนรหัสผ่านทุกตัวที่เป็น ChangeMe_*
# คู่ access/secret key ต้องตรงกันระหว่างสองไฟล์นี้ --
# .env ถูกอ่านโดย elt-runner; seaweedfs_s3_config.json ถูกอ่านโดยตรงจากตัว SeaweedFS เอง
# (ไม่ได้แทรกค่าจาก .env ให้อัตโนมัติ ต้องแก้ไขทั้งสองไฟล์ด้วยค่าที่ตรงกัน)

  2. เปิดใช้งานโครงสร้างพื้นฐาน (infrastructure)

    docker compose up -d warehouse-db landing-zone metabase
docker compose ps   # รอจน warehouse-db และ landing-zone แสดงสถานะ "healthy"

  3. Build และรันไปป์ไลน์

    docker compose build elt-runner
docker compose run --rm elt-runner

    เป็น batch job แบบรันครั้งเดียว ทำการรีเฟรชข้อมูลครบทั้ง Bronze -> Silver -> Gold ทุกครั้งที่รัน (idempotent — รันซ้ำได้ผลลัพธ์เดิม) ดึงข้อมูลจากแหล่งสด (live API) ทั้งหมด รวมถึงข้อมูลประชากร DOPA ย้อนหลัง 9 ปี (พ.ศ. 2560–2568) และรายงานใบอนุญาตแรงงานต่างด้าวจากกรมการจัดหางาน (DOE) ซึ่งครอบคลุมทั้งกรุงเทพมหานคร (10 เขตพื้นที่) และจังหวัดสมุทรปราการ/ฉะเชิงเทรา (ระดับจังหวัด) การครอว์ลข้อมูล HDC ทั้งหมด (119 รายงาน) เป็นขั้นตอนที่ใช้เวลานานที่สุด โดยทั่วไป 10-20 นาที (จำกัดความเร็วการเรียก API โดยตั้งใจ) — สังเกตบรรทัด [ingest_api_hdc] (N/119)... ที่เพิ่มขึ้นเรื่อย ๆ ถือเป็นเรื่องปกติ ไม่ใช่การค้าง (hang) แหล่งข้อมูลที่ล่ม (DDS, OSM — ยืนยันแล้วว่าถูกบล็อกจากต้นทาง) จะบันทึกคำเตือนและไปป์ไลน์จะทำงานต่อไป ไม่หยุดการติดตั้งทั้งหมด

คอนเทนเนอร์ Metabase ที่สร้างใหม่จะยังไม่มีบัญชีผู้ดูแลระบบ เปิดครั้งแรกจะเจอหน้าตั้งค่า (setup wizard):

วิธีที่ 1 — ใช้หน้าเว็บ (UI wizard)

เปิด http://localhost:3000 ทำตามขั้นตอน: สร้างบัญชีผู้ดูแล จากนั้นเพิ่มการเชื่อมต่อฐานข้อมูล (MySQL, host warehouse-db, port 3306, database gold, user metabase_ro, password = ค่า DWH_METABASE_RO_PASSWORD จาก .env)

วิธีที่ 2 — ใช้ API (เหมาะกับการ automate)

ดูขั้นตอนแบบละเอียดในเอกสารภาษาอังกฤษ (docs/05_runbook.html หัวข้อ Metabase Bootstrap) ซึ่งมีตัวอย่างสคริปต์ PowerShell ครบถ้วน

มี "Sample Database" (ชุดข้อมูลตัวอย่างของ Metabase เอง) ถูกเพิ่มมาอัตโนมัติตอนตั้งค่า — ลบออกได้เพื่อความสะอาด ของพื้นที่ทำงาน ผ่าน DELETE /api/database/1

งานประจำวัน

  • รันไปป์ไลน์ใหม่ ได้ทุกเมื่อ: docker compose run --rm elt-runner — เป็น idempotent (landing zone จะข้ามการบันทึกไฟล์ที่เนื้อหาไม่เปลี่ยน แต่ละชั้นข้อมูลจะ drop/create ตารางของตัวเองใหม่ทุกครั้ง)
  • Rebuild image ของ elt-runner หลังแก้โค้ด Python หรือ requirements ใด ๆ: docker compose build elt-runner — สำคัญ: ไฟล์ pipeline/*.py ถูกฝังเข้า image ตอน build (ไม่ใช่ bind-mount แบบไฟล์ SQL) ดังนั้นแก้ไฟล์ Python แล้วต้อง build ใหม่ก่อนรัน ไม่เช่นนั้นการแก้ไขจะไม่มีผลใด ๆ (เคยเป็นสาเหตุของบั๊กที่ดูเหมือนแก้แล้วแต่ยังเจอ error เดิมซ้ำในระหว่างพัฒนาโครงการนี้)
  • เบราส์ landing zone ที่ http://localhost:8888/buckets/landing-zone/ (หน้าเว็บ Filer ของ SeaweedFS เอง — ดูไฟล์แยกตามแหล่งข้อมูล ดาวน์โหลด/อัปโหลดได้โดยตรง)

การแก้ไขปัญหาที่พบบ่อย

DDS ตอบกลับ error 500 ทุกครั้ง ตรวจสอบว่ามีคำว่า "could not find driver (Connection: pgsql...)" ใน response หรือไม่ — เป็นปัญหาฝั่งเซิร์ฟเวอร์ DDS เอง (ไม่มี PostgreSQL driver) ไม่สามารถแก้ไขจากฝั่งนี้ได้ รอแล้วลองรัน ingest_api_dds.run() ใหม่เป็นระยะ
NSO ตอบกลับ HTTP 418 (หน้า block) WAF ของ NSO บล็อก User-Agent เริ่มต้นของ requests/curl ตรวจสอบว่า ingest_api_nso.py ยังส่ง User-Agent: Mozilla/5.0 kmch-phase3-nso/1.0 อยู่หรือไม่
การค้นหาสถานพยาบาลผ่าน OSM ได้ HTTP 406 จากทุก Overpass endpoint ยืนยันแล้วว่า Overpass public instance บล็อก network origin นี้ ไม่เกี่ยวกับโค้ดนี้ — ไม่ส่งผลต่อ dim_facility ที่ยังมี KMCH เพียง 1 แถว (เพราะ OSRM คำนวณระยะทางไปยังพิกัด KMCH ตรง ๆ อยู่แล้ว ไม่ต้องรอ OSM)
คอนเทนเนอร์ landing-zone แสดงสถานะ "unhealthy" healthcheck ของมันถือว่า HTTP response ใด ๆ (แม้แต่ 403) เป็น healthy — ถ้าเจอ unhealthy จริง มักเกิดจากไฟล์ seaweedfs_s3_config.json หายไป (คัดลอกจาก .example หากยังไม่ได้ทำ)
ไปป์ไลน์ดูเหมือนค้างอยู่ 15-20 นาที นั่นคือการครอว์ล HDC (119 รายงาน x หลายปี x 2 โซน จำกัดความเร็ว 0.6 วินาทีต่อคำขอ) ไม่ใช่การค้าง — สังเกตบรรทัด [ingest_api_hdc] (N/119)... ที่เพิ่มขึ้นเรื่อย ๆ

รีเซ็ตทั้งหมด

docker compose down -v   # ลบทั้งคอนเทนเนอร์และ volume -- ข้อมูลที่ landed ไว้, ข้อมูลคลัง, สถานะ Metabase หายทั้งหมด
docker compose up -d warehouse-db landing-zone metabase
docker compose run --rm elt-runner
# จากนั้นทำขั้นตอน "ตั้งค่า Metabase" ใหม่ -- volume ใหม่ = ต้องตั้งค่าใหม่ทั้งหมด
คำสั่งนี้ลบทุกอย่าง: ทุกไฟล์ที่ landed ไว้ใน SeaweedFS, ทุกแถวข้อมูลใน Bronze/Silver/Gold, และ Metabase ทั้งระบบ (บัญชีผู้ดูแล, คำถามที่บันทึกไว้, แดชบอร์ด) ใช้คำสั่งนี้เฉพาะเมื่อต้องการเริ่มต้นใหม่ทั้งหมดจริง ๆ
