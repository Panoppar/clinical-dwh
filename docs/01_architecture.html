Data Flow

Live Thai government APIs + 2 public geo/routing services, no flat files, no manual exports. Raw API responses land in a versioned, content-hashed S3-compatible store before Bronze shreds them into tables.

Each live source is wrapped in run_pipeline.run_live_source(), which logs a failure and continues rather than aborting the whole run — confirmed necessary in practice (DDS's and Overpass's outages would otherwise block Silver/Gold on every pipeline run). One exception to the usual Bronze-all→Silver-all→Gold-all ordering: OSRM's ingest needs gold.dim_area's unit centroids as its source points, so it runs between Gold dimensions and Gold facts, not alongside the other live sources.

Services (docker-compose.yml)

warehouse-db

MySQL 8.0, hosts bronze/silver/gold schemas. dwh_elt (full DML/DDL) and metabase_ro (SELECT on gold.* only) accounts.

elt-runner

One-shot Python batch job, runs the full Bronze→Silver→Gold pipeline, then exits. Re-run any time with docker compose run --rm elt-runner.

landing-zone

SeaweedFS, S3-compatible. MinIO was the original choice but its free container distribution was discontinued across every registry as of this build (confirmed by direct testing).

metabase

BI tool, connects only to warehouse-db.gold via the read-only account. Dashboards are built manually via the Metabase UI, not by the pipeline.

Known Issues

DDS backend down since 2026-10-25. Every request returns a server-side error: "could not find driver (Connection: pgsql...)" — a missing/misconfigured PostgreSQL PHP driver on DDS's own server, confirmed by repeated direct testing, unrelated to this code. Re-run ingest_api_dds.run() once it recovers; the landing zone exists specifically because DDS "keeps no archive: a finished year it stops serving cannot be fetched again."
Overpass (OSM) blocked since 2026-10-26. The public overpass-api.de instance (incl. its lz4 mirror) returns HTTP 406 on every request, confirmed from both the elt-runner container and the host machine directly — a block on this network origin, unrelated to this code. ingest_api_osrm.py does not depend on this succeeding: it always computes the travel matrix from every dim_area unit to the fixed KMCH coordinate.
PII exclusion, DIW. The source sheet carries operator_name (factory owner's personal name) and phone. Both are read off the sheet (to keep column positions aligned) and dropped before any row is built, logged, or inserted — they never reach Bronze, Silver, Gold, or any output.
fact_hdc_observation.geo_key is often NULL. Only ~40% of pivoted HDC records resolve to a geography — this is correct: reports using the disease_ranking or unsupported layout (see Silver EAV notes) don't carry a resolvable area name per record.
